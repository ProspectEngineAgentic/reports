Research Plan — Building the 500-Prospect List

Prospect Engine Inside Sales — Saiful Islam Saif. Date: 2026-05-27.

The goal is 500 scored, verified, tiered prospects across Singapore → Australia → Germany → Malaysia, every one researched, none random. This plan is the repeatable engine that fills that list and keeps it fresh. It pairs with 05-BUYING_INTENT_FRAMEWORK.md (the gate + scoring) and 04-MARKET_RESEARCH.md (where buyers cluster per market).

3. The weekly research operating rhythm

To reach 500 without a single random name, run a steady cadence rather than one giant scrape:

Cadence Action Output
Daily Process one source slice (one accelerator cohort, or one Apollo sheet segment, or one classic-search query) through fit gate → quick intent pass ~15–25 new fit-passed candidates added to DRAFT
Daily Live-verify + score yesterday's candidates (the checklist in §3 of the intent framework) Verified, tiered rows promoted to the live queue
Weekly Re-score nurture pool + uncontacted Tier 1/2; dedupe; refresh counts toward the 500 Clean, ranked master list
Weekly Replenish: if verified queue < 1 week of outreach volume, source more List never runs dry

At ~20 verified prospects/day, the 500 verified target is reached in roughly 5–6 working weeks, and the list stays current because re-scoring is built in. Tier-1 hot prospects jump the queue.

4. The master list schema (what every row carries)

The starter CSV (Leads/lead_list_v1.csv) uses the sourcing columns. As rows are verified + scored, they gain:

market, company, company_type, employees_est, stage_or_funding, person_name, person_title, persona, linkedin_url, company_website, why_fit, suggested_angle, case_study_to_lead, source, verification_status, intent_score, fit_grade, final_score, tier, live_signal, personal_hook, last_touch, next_action, status

status lifecycle: draft → verified → queued → connect_sent → connected → m1_sent → ... → replied(stop) / meeting / not_now(nurture) / disqualified.

This single sheet is the source of truth and feeds the outreach tracker in 06.

5. Verification SOP (per row, before it can be contacted)

Identical to the checklist in 05-BUYING_INTENT_FRAMEWORK.md §3. The non-negotiables, restated because they are the project's #1 invariant:

  1. Open the live profile. Confirm title, company, headcount. Titles drift — never trust the sheet alone.
  2. Read their last 3 posts/comments. Capture live_signal + personal_hook. This is what makes the message non-automated.
  3. Confirm persona + service pillar.
  4. Dedupe against all PE client folders and active campaigns.
  5. Exclusion sweep (competitor / B2C / enterprise-SDR).
  6. Only then score, tier, and queue.
